Step 0 · before the journey

Where the numbers come from: training

Every matrix in the steps ahead (the embedding table, WQ, WK, WV, the MLP weights, the output layer) starts as random numbers. Training is what turns them into a language model. The model reads a huge amount of text and, at every position, guesses the next token. Each guess is scored, and backpropagation works out, for every single number in the model, which direction would have made the right answer a little more likely. Every number takes a tiny step in that direction. Repeat this billions of times.

loss = −log p(actual next token)    every weight w ← w − η · ∂loss/∂w
Key ideaNobody designs the embeddings or WQ, WK, WV by hand. They are whatever numbers made next-token prediction work best on the training text. When you use the model (steps 1 to 9), they are frozen and only read.

Presenter notes
  • Press Train. The dots start in a random clump. Words that are followed by similar words (cat and dog, mat and rug) drift together, because giving them similar vectors is the easiest way to predict what comes next.
  • This demo is a real training run in your browser: a tiny model with 2 numbers per word, trained by gradient descent on the sentences shown, including yours. Real models do the same with thousands of numbers per token and a full transformer in between.
  • The loss starts at about ln(vocabulary size), which is what pure guessing scores. It can’t reach zero, because the same word can be followed by different words.
  • WQ, WK and WV are trained exactly the same way: the gradient flows back through attention into them. Nobody tells a head to “look at the previous word”; it ends up doing so because that lowers the loss.
Step 1 of 9

Tokenization: text becomes numbers

A neural network cannot read letters. The tokenizer cuts the text into tokens (whole words, pieces of words, or punctuation) and swaps each one for its ID in a fixed vocabulary. Each ID then picks out one row of the embedding table: a learned list of numbers that stands for that token’s meaning.

Key ideaFrom here on, every token is a vector. This demo uses 16 numbers per token; GPT‑2 small uses 768. The table itself was learned in step 0: training kept adjusting each row until the vectors were useful for predicting the next word.

  • Real tokenizers (BPE) learn common chunks from data, so “unbelievable” might become “un” + “believ” + “able”. Try typing a long, rare word in the input box.
  • The vocabulary is fixed before training: GPT‑2 has 50,257 tokens.
  • The embedding numbers start random and are learned during training, so similar words end up with similar vectors.
Step 2 of 9

Positional encoding: where is each word?

Attention looks at all tokens at once, so on its own it has no sense of order: “dog bites man” and “man bites dog” would look identical. We fix that by adding a position signal to each embedding. The original transformer uses sine and cosine waves of different wavelengths, so every position gets a unique fingerprint.

PE(pos, 2i) = sin(pos / 10000^(2i/d))    PE(pos, 2i+1) = cos(pos / 10000^(2i/d))
Presenter notes
  • Low dimension pairs wiggle fast (they tell neighbours apart); high pairs change slowly (they tell early from late). Drag the slider to show this.
  • Many modern models (Llama, GPT‑NeoX) use rotary embeddings (RoPE) instead, which rotate the queries and keys by position. The purpose is the same.
  • The result, embedding + position, is the input to the first decoder block.
Step 3a of 9

Where Q, K and V come from

Queries, keys and values are not extra inputs. Each one is the token’s vector x (from step 2) multiplied by a learned weight matrix. The same three matrices WQ, WK and WV are applied to every token at every position; only x changes. Each output number is a weighted sum of all 16 input numbers, with the weights taken from one column of W.

q = x · WQ    k = x · WK    v = x · WV    (x is 1 × 16, each W is 16 × 16, learned in step 0)
AnalogyThink of a library. The query is what you are looking for, each book’s key is the label on its spine, and its value is what is written inside. WQ, WK and WV are three different learned ways of reading the same token.

Presenter notes
  • Point at one output cell: it is just x₀·W₀ⱼ + x₁·W₁ⱼ + … + x₁₅·W₁₅ⱼ. Sixteen multiplies and a sum.
  • Why three different matrices? Because what a word is looking for (query) differs from how it should be found (key) and from what it should pass on (value). Training discovers useful versions of all three.
  • In this demo WQ, WK, WV are fixed random numbers. In GPT‑2 small each is 768 × 768 = 589,824 learned numbers, in each of 12 layers.
Step 3b of 9

Masked self-attention: each word looks back

Every token asks a question (its query), advertises what it contains (its key), and carries information to share (its value). A query is compared with every key; the best matches get the most weight. The mask hides future tokens, because when the model writes text, the future does not exist yet.

Attention(Q, K, V) = softmax( Q·Kᵀ / √dk + mask ) · V
Head

Rows are queries (the token asking). Columns are keys. Click a row.

Presenter notes
  • Dividing by √dk keeps the scores in a range where softmax does not saturate.
  • The mask sets future positions to −∞, and e−∞ = 0, so they get exactly zero weight.
  • The first token can only attend to itself. The last token can see the entire prompt, which is why its vector is used to predict the next word.
  • This all happens as one matrix multiply, so a GPU processes every position in parallel during training.
Step 4 of 9

Add & Norm: keep the original, keep it steady

Attention’s output is not used on its own. It is added back to the vector that went in (a residual connection), so the model only has to learn what to change. Then layer normalization rescales each token’s vector to mean 0 and standard deviation 1, which keeps numbers stable through dozens of stacked layers.

x₁ = LayerNorm( x + Attention(x) )    LayerNorm(v) = γ · (v − mean) / std + β
Token
Presenter notes
  • The residual path is a highway: gradients flow straight through it, which is what makes 100‑layer networks trainable.
  • Watch the stats column: after LayerNorm the mean is 0.00 and the standard deviation is 1.00, whatever the input was.
  • The original paper normalizes after adding (post-norm, shown here). GPT‑2 and most modern models normalize before each sub-layer (pre-norm).
Step 5 of 9

Multi-head: many ways of looking, in parallel

One attention pattern cannot capture everything. So the model runs several heads side by side, each with its own Q, K and V weights and a slice of the vector. One head may track the previous word, another the subject of the sentence. Their outputs are concatenated and mixed by one more matrix, WO.

MultiHead(x) = Concat(head₁, head₂, head₃, head₄) · WO    4 heads × 4 dims = 16
Attention pattern of each head (rows attend to columns)
Presenter notes
  • The four patterns here are deliberately shaped to resemble head types that researchers have found in trained models: previous-token heads, heads that park on the first token, and content-matching heads.
  • Heads are cheap: splitting 16 dims into 4 × 4 costs the same compute as one big head.
  • GPT‑2 small has 12 heads in each of its 12 layers, 144 heads in total.
Step 6 of 9

The MLP: each word thinks on its own

Attention moves information between tokens. The feed-forward network (MLP) then processes each token separately: it expands the vector to 4× its width, applies a non-linearity (GELU), and projects it back. Much of the model’s factual knowledge is thought to be stored in these weights. Then comes a second Add & Norm.

MLP(x) = W₂ · GELU( W₁·x + b₁ ) + b₂    16 → 64 → 16

Step 7 of 9

Linear + softmax: a score for every word

Only the last token’s vector is needed to predict what comes next. A final linear layer multiplies it by the unembedding matrix, producing one raw score (a logit) per vocabulary entry. Softmax turns those scores into probabilities that sum to 100%. Temperature controls how sharp that distribution is.

p(word) = exp(logit / T) / Σ exp(logit / T)
T = 1.00

  • Drag temperature toward 0.1: the top word takes nearly all the probability. Drag toward 2: the distribution flattens and unlikely words gain a chance.
  • Many models reuse the embedding table from step 1 as WU (weight tying).
  • A real vocabulary has 50k to 200k entries, so this is one very long vector of probabilities.
Step 8 of 9

Next-word prediction: pick one token

The model does not output a word. It outputs a probability distribution, and a decoding strategy chooses from it. Greedy always takes the most likely token: predictable, but it can get repetitive. Sampling rolls weighted dice among the top candidates, which gives more varied and natural text.

Step 9 of 9

The loop: append, repeat, write

Generation is just steps 1 to 8 on repeat. The chosen token is appended to the input and the whole decoder runs again, now with one more token of context. This is called autoregressive generation. It continues until the model emits an end token or hits a length limit.

Presenter notes
  • Real systems cache each layer’s keys and values (the KV cache), so each new step only computes attention for the newest token instead of redoing the whole prompt.
  • Each turn of the loop sends the full text so far to the model and gets back a fresh probability distribution for the next token. Nothing is scripted.
  • Greedy decoding can get stuck repeating itself; switching to sampling in step 8 usually fixes that.
  • Chat models work the same way: your message is the prompt, and the reply is generated one token at a time.

Deep learning from zero
Basics 1 of 5

A neural network is a machine full of dials

A neural network is a function: numbers go in, a number comes out. Inside are many small dials (called weights). How the dials are set decides what the network does. Deep learning means we do not set the dials by hand. We show the network examples with known answers, and a procedure turns every dial a little at a time until the answers come out right.

Our running exampleIs a fruit good to eat? We describe each fruit with two numbers between 0 and 1: how sweet it is and how soft it is. Good fruit is sweet and a little soft, but not mushy. We never write that rule down. The network has to discover it from 60 example fruits.

  • The two phases are the most important idea on this page. ChatGPT was trained once; every reply you get is inference.
Basics 2 of 5

One neuron: multiply, add, squash

A neuron takes its inputs, multiplies each by a dial (its weight), adds them up with one more dial (the bias), and squashes the total into a number between 0 and 1 (the activation). A big weight means “this input matters a lot”; a negative weight means “this input counts against”. Turn the dials and watch the neuron respond.

output = σ( w₁ × sweetness + w₂ × softness + b )    σ(z) = 1 / (1 + e−z)

Basics 3 of 5 · training phase

Training: let the examples turn the dials

Our network has 3 hidden neurons (A, B, C) feeding one output neuron: 13 dials in total. They start random, so its guesses are random. Training repeats one simple loop for every example fruit: guess, measure the error, work out which way each dial should turn to shrink that error (backpropagation), and turn every dial a little (gradient descent). The shaded map shows what the network currently believes about every possible fruit.

Presenter notes
  • First, challenge someone to fix the map by turning dials by hand. With 13 dials it is already hard; GPT‑3 has 175 billion. That is why training is automatic.
  • Use “Explain one step” two or three times: each fruit nudges all 13 dials only slightly.
  • Then press Train. Each “pass” (epoch) shows the network all 60 fruits once. Watch the loss fall and the shaded region settle into “sweet, but not mushy”.
  • Too high a learning rate makes the dials overshoot; too low and training crawls. Try both.
Basics 4 of 5 · inference phase

Inference: freeze the dials, ask a new question

Training is over, so the dials are locked. Now give the network a fruit it has never seen. The numbers flow forward once, from the inputs, through the hidden neurons, to the output, and out comes an answer. Nothing is learned here and no correct answer is needed. This is what happens every time you use an AI model.

These dials have not been trained yet, so the answers will be poor. or go back to step 3.

Presenter notes
  • Pick a fruit far from any training example. The network still answers, because it learned a pattern, not a list. That is called generalization.
  • Inference is one pass of multiply, add, squash. It is cheap compared with training, which is why a model trained once can serve millions of people.
Basics 5 of 5

From 13 dials to 175 billion

Large language models are built from exactly these parts: neurons that multiply, add and squash, stacked in many layers. The task changes from “good fruit?” to “what is the next word?”, and the dial count grows enormously. Training is the same loop: guess the next word in real text, measure the error, turn every dial a little. Inference is the same forward pass, repeated once per generated word.
