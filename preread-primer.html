Decoder Primer

Eight ideas in plain words. If these are familiar when we start, we can spend the session on how the decoder works instead of on the vocabulary.

The one sentence to remember

A decoder-style language model does one thing: it reads the text so far, scores every possible next token, picks one, adds it, and repeats.

The journey in one glance

Everything in the session happens on the way from a prompt to the next token. This is the route, and the eight ideas below are what you need for it.

  1. 1 · Text in“Approve the invoice if”
  2. 2 · Tokenscut into pieces, each given an ID
  3. 3 · Vectorseach token becomes a list of numbers
  4. 4 · Mix and thinkwords share information, then each word is processed
  5. 5 · Scoresevery possible next token gets one
  6. 6 · Percentagesscores become probabilities
  7. 7 · Pick onefor example “the”
  8. 8 · Add itthen go round again
  9. The loop repeats until the answer is finished

Eight ideas

Each one has the same three lines: what it is, an everyday automation comparison, and where it will come up.

1Token

Models do not read letters. Text is cut into pieces called tokens, usually a word or part of a word, and each piece is swapped for an ID number.

“Approve the invoice if” → Approve | the | invoice | if
Think of it asSplitting a message into fields before a workflow can use it. AI usage limits and pricing are counted in tokens, not words.
In the sessionThe very first step.

2Vector

A vector is a list of numbers that describes one thing. The order is fixed: position 1 always means the same thing.

ticket = [urgency 7, order value 3, age 5]
Think of it asA spreadsheet row where every column is a number.
In the sessionEvery token becomes a vector and stays one all the way through.

3Embedding

An embedding is the starting vector for a token, looked up in a big table. Words used in similar ways get similar vectors, so “invoice” and “receipt” end up close together and “invoice” and “password” do not.

Think of it asA lookup table keyed by token ID. The twist: nobody filled it in by hand. Training did.
In the sessionRight after tokenisation.

4Dot product

Multiply two vectors position by position, then add up. You get one number that says how well they match. A big positive number means they point the same way.

[2, 1, 0] · [1, 3, 5] = 2×1 + 1×3 + 0×5 = 5
Think of it asA lead score: each fact about a lead is multiplied by how much it matters, then added up.
In the sessionHow a word decides which other words matter to it. This is the heart of attention.

5Matrix and weights

A matrix is a table of numbers. Multiplying a vector by it turns that vector into a new one. The numbers inside the model’s matrices are its weights, the settings it learned.

Think of it asA set of scoring rules applied to every row at once. The model has many such sets, and the rules were found, not written.
In the sessionWhenever you hear “where does this come from?”, the answer is a learned matrix.

6Softmax

Softmax turns raw scores into percentages that add up to 100%. The highest score gets the biggest share, and nobody gets exactly 0% or 100%.

scores [2, 1, 0] → 67% | 24% | 9%
Think of it asSeveral classifiers each give a confidence. Softmax turns them into one set of shares you can route on.
In the sessionTwice: to decide how much to listen to each word, and to turn the final scores into next-token probabilities.

7Training and using

Training happens once, on a huge amount of text: guess the next token, measure the error, nudge every weight. Using the model, which is called inference, keeps the weights frozen. A chat does not teach the model anything.

Think of it asConfiguring and testing a rule set once, then simply running it. Anything the model should know has to be in the prompt you send.
In the sessionStep 0 covers training. Everything after it is inference.

8The next-token loop

The model gives every possible next token a probability, one is picked, it is added to the text, and the whole thing runs again. Temperature sets how adventurous the pick is: low is safe and repeatable, high is varied. The context window is how much text the model can read at once.

Think of it asA loop whose output becomes its own next input. Longer answers mean more passes, so they take longer.
In the sessionThe last steps, and the reason the same prompt can give different answers.
Safe to skip for now

You will also hear about non-linearity, residual connections, normalisation and multiple heads. Each gets a short explanation in the session when we reach it, so there is nothing to prepare.

Three questions to bring

No need to answer them. Just have them in mind while you read.

  1. If the model only reads the text you send it, what does that mean for what you put in a prompt?
  2. Why might the same prompt give two different answers?
  3. Where in your own automations does something repeat with its own output as the next input?

Words you will hear

Prompt
The text you give the model.
Parameter
Another word for a weight. “175 billion parameters” means 175 billion learned numbers.
Layer, block
One stage of computation. The model repeats the same kind of block many times.
Logit
A raw score before softmax.
Attention
How each word looks back at earlier words and borrows what is useful.
Decoder
The part of a transformer that writes text one token at a time.
