Vector

A vector is an ordered list of numbers. Each position means one thing about the item.

AutomationA row in a spreadsheet where every column is a number. A support ticket might be [urgency 7, order value 3, age in days 5].
In the decoderEvery token is turned into a vector (768 numbers in GPT-2 small) and stays a vector all the way through the model.
Try it · a ticket as a vector

The order matters: position 1 always means urgency. Two vectors can only be compared if they use the same positions for the same things. The count of numbers is the vector’s dimension; this one is 3-dimensional.

Topic 2core3 min↑ list

N-dimensional vector space

A vector with n numbers is a point in n-dimensional space. Things that are similar end up near each other.

With 2 numbers you can plot a point on a sheet of paper. With 3, in a room. A vector with 768 numbers is a point in a 768-dimensional space. We cannot picture that, but the maths (distances, angles, comparisons) works exactly the same way as on the paper.

AutomationPlot every past ticket as a point. Refund requests clump together, password problems clump together. A new ticket can be routed by finding which clump it lands in.
In the decoderMeaning is stored as position in this space. Words used in similar ways sit close together, so the model can treat them alike.
Try it · a 2-D map of words (click a word)

Real embeddings are not drawn by hand. They are learned, and they have hundreds or thousands of dimensions, so a map like this is a squashed picture. “Close” is measured with distance or, more often, with the angle between two vectors (next topic).

Topic 3core3 min↑ list

Dot product

Multiply two vectors position by position, then add up. The result is one number: a match score.

a · b = a₁×b₁ + a₂×b₂ + a₃×b₃
AutomationA lead-scoring rule. Weights [2, 1, 0] mean “visits count double, demo requests count once, company size does not count”. The dot product with a lead’s numbers is its score.
In the decoderAttention scores how well one token matches another with a dot product. Almost every number in the model is the result of one.
Try it · dot product, with A fixed at [2, 1, 0]

A large positive result means the two vectors point the same way. Near zero means unrelated. Negative means opposite. The score also grows when the vectors are longer, which is why attention divides it by the square root of the dimension, and why people also use cosine similarity, the dot product with the lengths divided out.

Matrix multiplication

A matrix is a table of numbers. Multiplying by it computes a dot product for every column, so one vector becomes a new vector.

AutomationOne mapping table applied to every row of a batch. Each output column is a scoring rule, and the matrix holds all the rules at once.
In the decoderQ, K and V are made with matrix multiplications. So are the MLP, the output of attention, and the final score for every word. These matrices are the model’s learned weights.

The shape rule: the inner sizes must match (here 3 and 3), and the result takes the outer sizes (3 rows, 2 columns). A matrix with different column count changes the length of every vector. The decoder mostly uses square-ish matrices so vectors keep their size, and one large one at the end to score the whole vocabulary.

Topic 5core3 min↑ list

Softmax

Softmax turns a list of raw scores into percentages that add up to 100%, keeping the order: the biggest score gets the biggest share.

AutomationSeveral classifiers each return a confidence score. Softmax turns them into one set of shares you can route on: 70% “billing”, 20% “technical”, 10% “other”.
In the decoderIt turns attention scores into “how much to listen to each earlier word”, and it turns the final scores into probabilities for every possible next token.
Try it · softmax with temperature

Raising a score by 1 multiplies that item’s weight by about 2.7 (that is the number e), so softmax is generous to the leader but never gives anyone exactly 0% or 100%. Temperature divides the scores first: low temperature makes the leader dominate, high temperature spreads the shares out.

Topic 6core3 min↑ list

Tokens and tokenisation

A model cannot read letters. Text is cut into pieces called tokens, and each token is replaced by a whole-number ID.

AutomationParsing an incoming message into fields before a workflow can use it. Limits and pricing for AI models are counted in tokens, not words, so this is the unit you will plan around.
In the decoderStep 1. The prompt becomes a list of IDs, and the model’s whole job is to predict the next ID.
Try it · a toy tokeniser

Common words are usually one token. Rare or long words are split into pieces. The pieces are not chosen by hand: a method such as byte-pair encoding finds the most useful ones from a large body of text. GPT-2’s vocabulary has 50,257 tokens. As a rough rule for English, one token is about four characters, or three quarters of a word. (This toy only imitates that: a short list of common words stays whole and everything else is cut into 4-letter chunks. The IDs are made up.)

Topic 7core3 min↑ list

Embeddings

An embedding is the vector for a token. It comes from a big table with one row per token ID, so the lookup is just “fetch row number 25637”.

AutomationA lookup table keyed by ID that returns a fixed record. The twist: nobody writes the records. Training adjusts them until tokens used in similar ways have similar rows.
In the decoderStep 1b. The embedding is the first vector a token gets, before any other word has been taken into account. GPT-2 small uses 768 numbers per token.
Try it · look up a row, then find its nearest neighbours

The six columns here were invented so you can read them (money, paper, login, delivery, action, formality). In a real model the columns have no names. Meaning is spread across all of them, and you only learn what they encode by comparing rows.

Two details to remember. First, the same token always gets the same row, wherever it appears; the decoder’s later steps are what make the vector depend on context. Second, the position of a token is added to its vector separately, because a lookup table alone says nothing about word order.

Topic 8helpful2 min↑ list

Reading shapes (T × C)

The session writes sizes as rows × columns. T is the number of tokens, C is the number of numbers per token.

AutomationRows in a batch and columns in each row. If the columns do not line up, the step fails, and the same is true here.
In the decoderAlmost every step turns one T × C table into another T × C table. Knowing that makes the diagrams easy to follow.
Try it · follow the shapes through attention

The one shape to notice is the attention score table: T × T, one score for every pair of tokens. It grows with the square of the text length, which is one reason very long inputs cost more.

Topic 9core4 min↑ list

Weights, training and inference

The weights are the learned numbers: every embedding table and every matrix. Training sets them. Inference only reads them.

Training

Done once, by the model’s maker, on a huge amount of text. At every position the model guesses the next token, a score measures how wrong it was, and every weight is nudged a little to be less wrong. Repeat billions of times.

Inference

What happens every time you use the model. The weights are frozen. Text goes in, one pass runs through the same fixed matrices, and probabilities for the next token come out.

AutomationTraining is configuring and testing a rule set until it works. Inference is running the finished rules. The difference: the settings here number in the billions, and a search procedure sets them, not a person.
In the decoderThe question “where do the Q, K and V matrices come from?” always has the same answer: training. At use time, only the input changes.

A consequence for builders: a chat with a model does not teach it anything. It sees only the text you send, so anything it needs to know has to be in the prompt. “Memory” features work by saving text and putting it back into later prompts.

Topic 10helpful2 min↑ list

Non-linearity

Multiplying and adding only gives straight-line behaviour. A small bend between layers lets the model follow curves and “it depends” patterns.

AutomationAn IF rule: “do nothing below a threshold, act above it”. Without a step like that, a chain of calculations collapses into one calculation.
In the decoderInside the MLP, between its two matrices. GPT-2 uses GELU, a smooth version of ReLU.
Try it · a straight line versus a bend

Stack ten straight-line steps and you get one straight-line step. Put a bend between them and the stack can learn much more. This is what makes depth worth having.

Topic 11helpful3 min↑ list

Residual connections and normalisation

Two housekeeping habits keep a deep stack stable: add each step’s output back onto its input, and rescale the numbers to a standard range.

AutomationTrack changes. The original document stays, and each step only proposes edits on top of it. Normalising is like keeping every volume level in the same range.
In the decoderThe “Add & Norm” step, twice in every block. It is why 12 or 96 blocks can be stacked without the numbers blowing up or the original information being lost.
Try it · residual add, then normalise
Input x = [3, 9, 6]. A step proposes the change [1, −2, 0.5] × the size below.

Residual means: output = input + change, so the model only has to learn what to change. Layer normalisation subtracts the average of a token’s numbers and divides by their spread, so every vector has average 0 and spread 1 before the next step. You do not need to remember the formula, only that numbers are kept in a sensible range.

Probabilities, logits and sampling

The model does not output a word. It outputs a score (a logit) for every token in its vocabulary. Softmax turns those into probabilities, and a decoding rule picks one.

AutomationA router with confidence scores. You can always take the top route, or pick at random in proportion to the confidence. The first is repeatable, the second adds variety.
In the decoderSteps 7 and 8. This is also why the same prompt can give different answers, and what the “temperature” setting in an AI product controls.
Try it · choose the next token after “Approve the invoice if”
Press a button.

Greedy always picks the top token. Sampling picks at random in proportion to the probabilities. Top-k throws away everything outside the best k before sampling. Low temperature behaves almost like greedy; high temperature gives more unusual choices. For repeatable automation, set temperature low; for brainstorming, raise it.

Topic 13core4 min↑ list

Attention, in one paragraph

Each token asks a question (its query), every earlier token advertises what it holds (its key) and carries some content (its value). Match query to keys with dot products, turn the scores into shares with softmax, and take that share of each value.

AutomationA lookup with fuzzy matching: instead of fetching one exact record, you fetch a blend of all the records, weighted by how well each matches the request.
In the decoderStep 3. The session spends its longest stretch here. Everything in topics 1 to 5 shows up in these few lines.
Try it · a query looks at three earlier tokens

Read the table left to right: score is the dot product of the query with that token’s key (topic 3), share is softmax over the scores (topic 5), and the result is the sum of each value times its share. A causal mask hides later tokens, because a decoder writes left to right and the future does not exist yet. Real models do this with many queries at once (matrix multiplication, topic 4) and in several “heads” in parallel.

Topic 14core3 min↑ list

Autoregression and the context window

A decoder writes one token at a time. The token it picks is added to the text, and the whole text is fed back in to pick the next one.

AutomationA loop whose output becomes its next input. Each pass is a full run of the model, so long answers take many passes.
In the decoderStep 9. The context window is the most tokens the model can read at once. GPT-2 has 1,024; recent models have far more, but the limit still applies to your prompt plus the reply.
Try it · the loop, one pass at a time (illustrative output)

Practical consequences for building automations: output length costs time, the prompt and the reply share one token budget, and anything the model should use must be inside the window.

Check yourself

What is the dot product of [2, 1, 0] and [1, 3, 5]?

2×1 + 1×3 + 0×5 = 5.

A (3 × 4) matrix times a (4 × 2) matrix gives what shape?

3 × 2. The inner 4s must match and disappear.

Softmax turns the scores [2, 1, 0] into which kind of numbers?

Shares between 0 and 1 that add up to 1 (about 67%, 24% and 9%), with the biggest score getting the biggest share.

Where does an embedding come from?

A learned table with one row per token ID. Training adjusted the rows. At use time the model just looks up a row.

Does a model learn from your chat?

No. The weights are frozen at inference. It only reads the text you send in the current prompt.

What does lowering the temperature do?

It makes the top token dominate, so output is more repeatable and less varied.

Why does a decoder generate one token at a time?

Each token depends on all the ones before it, so it can only be picked once the previous ones exist. The chosen token is appended and the model runs again.

Glossary

Dimension
How many numbers a vector has.
Parameter, weight
One of the learned numbers. All of them together are the model.
Logit
A raw score before softmax.
Layer
One stage of computation. Deep means many layers.
Block
One decoder layer: attention plus MLP, each wrapped in Add & Norm.
Head
One of several attention patterns run side by side.
Context window
The most tokens the model can read at once.
Prompt
The text you give the model. It is the context for the first prediction.
